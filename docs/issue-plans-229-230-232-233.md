## #230: `VideoControls` play / pause / seek / volume buttons

### Current state (`src/components/learn/VideoControls.tsx`)

The issue says the buttons "appear to lack aria-labels". On `main` most of them already have one:

- Play/Pause (`'Pause'`/`'Play'`), Mute (`'Unmute'`/`'Mute'`), Fullscreen, captions, autoplay and the
  quality trigger are labelled. The seek bar is `aria-label="Seek"`, volume `aria-label="Volume"`,
  speed `aria-label="Playback speed"`.

So the real gaps are different from the issue text and need to be reproduced before changing anything:

1. **Missing `type="button"`** on play/pause, mute, quality trigger, quality options, autoplay and fullscreen.
   Harmless today, but wrong if the player is ever rendered inside a `<form>`.
2. **Invalid nested interactive roles in the quality menu:** `<ul role="listbox">` > `<li role="option">` >
   `<button>`. A button inside an option is not valid ARIA and screen readers may announce it poorly.
   The trigger also has `aria-haspopup="listbox"`, but there is no arrow-key handling or Escape handling,
   and focus is not moved into or back out of the menu.
3. **Seek slider has no human-readable value.** A native range reports a raw number of seconds
   (e.g. "73.5"). It needs `aria-valuetext` like "1:13 of 4:20".
   The volume slider similarly needs a percentage `aria-valuetext`.
   The slider is hidden below `md`, which is fine, but mute is then the only volume control on small screens.
4. **Time readout** (`current / duration`) is a plain `span`; it is fine to leave non-live, but verify nothing
   announces it every second.
5. **Focus styles are inconsistent:** only the captions button has `focus-visible:` styling; the other buttons
   rely on browser defaults on a dark gradient, which can be invisible.
6. **Icon `aria-hidden`:** captions icon has it; the others do not. Verify whether the installed lucide-react
   (0.383) already adds `aria-hidden` and add it explicitly where it does not.
7. **Dead code:** the component creates `shortcutsOpen`, `keyboardBtnRef` and renders `<KeyboardShortcutsModal>`,
   but nothing ever sets `shortcutsOpen` to true or attaches `keyboardBtnRef` to a button (the `Keyboard` icon
   is not imported here). Keyboard users therefore cannot reach the shortcuts help at all. See #229.

### Plan

1. Reproduce with keyboard only plus NVDA/VoiceOver on a lesson page; write the actual findings on the issue, since
   labels already exist. Ask the maintainer whether the issue refers to a different component version.
2. Add `type="button"` to all buttons and `aria-hidden="true"` to decorative icons.
3. Add `aria-valuetext` to seek (`formatDuration`) and volume (`NN%`).
4. Fix the quality menu semantics. Simplest valid option: make the trigger `aria-haspopup="true"` and
   `aria-expanded`, render the panel as a plain `div` with a group of `button`s using `aria-pressed`
   (or `role="menuitemradio"` with proper roving/arrow keys). Add Escape to close and return focus to the trigger.
5. Add a consistent `focus-visible:ring-2 ring-saffron-300` to every control (shared class constant).
6. Add a "Keyboard shortcuts" button (keyboard icon, `aria-label="Keyboard shortcuts"`, `aria-haspopup="dialog"`)
   wired to `keyboardBtnRef` / `setShortcutsOpen`, so the modal is reachable. Confirm with maintainers that this is intended
   to ship, since the code looks like it was removed on purpose.
7. Tests (`VideoControls.test.tsx`, new): every control has an accessible name (`getByRole('button', { name })`),
   toggled states update the name, sliders expose `aria-valuetext`, quality menu opens/closes with keyboard and Escape,
   and an axe run reports no violations.

### Verification

Keyboard-only pass (Tab order, Space/Enter on each control), screen reader pass, `npm run test`, `npm run lint`
(jsx-a11y), `npm run format`. The existing `e2e/video-player.spec.ts` must still pass.

## #229: `KeyboardShortcutsModal` focus trap

### Current state

- `src/components/learn/KeyboardShortcutsModal.tsx` already uses the shared hook
  `useMobileDrawerFocusTrap` from `src/lib/hooks/use-focus-trap.ts`, has `role="dialog"`, `aria-modal`,
  `aria-labelledby`, a close button and a "Close" button. The hook is also used by `components/layout/Header.tsx`
  for the mobile drawer, so the consistency check in the issue is: two consumers, both via the same hook.
- The hook is named after one consumer (`useMobileDrawerFocusTrap`) in a file called `use-focus-trap`.

Gaps found in the hook (affect both consumers):
1. **Focus is "restored" on first mount.** The restore effect runs whenever `isOpen` is false, including on the
   initial render, so mounting the component calls `triggerRef.current?.focus()` and can steal focus on page load
   (e.g. the hamburger or the shortcuts button) before the user has opened anything. It should only restore after
   a true -> false transition.
2. **The trap effect depends on `onClose`.** Both callers pass a new inline function every render, so the effect
   tears down and re-runs on every parent render, and each re-run calls `focusable[0]?.focus()`. A parent re-render
   while the modal is open (the video player re-renders on every `timeupdate`) moves focus back to the first
   control. Fix by keeping `onClose` in a ref and depending only on `isOpen`.
3. **`offsetParent !== null` filter** hides `position: fixed` descendants and everything in jsdom, so the trap can
   see zero focusable elements. Use a visibility check that works for fixed elements
   (`getClientRects().length > 0`) and make it testable.
4. **The Escape listener is on `document`** and calls `preventDefault` but not `stopPropagation`, so Escape inside the
   player can also trigger the player's own key handling or exit fullscreen. Verify and stop propagation.
5. The modal has no initial focus target contract: it focuses the first focusable (the X button). That is acceptable;
   document it.
6. The modal is unreachable right now (see #230 item 7), which blocks the manual reproduction step. Reproduce by
   temporarily wiring the trigger locally.

### Plan

1. Reproduce: wire a temporary trigger locally, open the modal with the keyboard, Tab/Shift+Tab around, Escape,
   check where focus lands after close, and note the focus-on-mount behaviour with a button ref present.
2. Fix the hook: ref for `onClose`, previous-open tracking for restore, robust focusable filter, optional
   restore-to-`document.activeElement` fallback when `triggerRef.current` is null.
3. Rename for clarity (`useFocusTrap`, keep `useMobileDrawerFocusTrap` as a deprecated re-export) only if the maintainers
   agree, to keep the diff small.
4. Ensure the modal's own markup is fine: keep `role="dialog"`/`aria-modal`; add `aria-describedby` only if useful.
5. Tests:
   - `use-focus-trap.test.tsx`: focus moves in on open; Tab from last wraps to first; Shift+Tab from first wraps to last;
     Escape calls `onClose`; focus returns to the trigger after close; **does not** move focus when mounted closed;
     parent re-render while open does not reset focus.
   - `KeyboardShortcutsModal.test.tsx`: renders nothing when closed; has the dialog role and name; Close buttons call `onClose`;
     axe has no violations.

### Verification

Manual keyboard pass in the lesson player, `npm run test`, lint, format; re-check the Header mobile drawer, since it shares the hook.

## #232: E2E for the instructor revenue dashboard

### Current state

- The issue names `src/app/instructor/layout.tsx` as the surface, but that layout only wraps `/instructor/courses/new`.
  The revenue dashboard is `src/app/dashboard/instructor/page.tsx` (stats, `RevenueChart`, `RevenueDateRangePicker`),
  and the course list with `BulkActionBar` is `src/app/dashboard/instructor/courses/page.tsx`. The spec should target
  `/dashboard/instructor` and `/dashboard/instructor/courses`; worth confirming on the issue.
- Auth: `middleware.ts` redirects `/dashboard/*` to `/login` without a `sorobanlard_token` cookie, so the spec must set
  the cookie and localStorage like `e2e/video-player.spec.ts` does.
- Data: stats come from `usersApi.getInstructorStats()` (mockable via `page.route`). **The chart data is not from an API:**
  `generateRevenueData()` in the page uses `Math.random()` after a 500 ms timer. "Verifying chart data" is therefore
  not deterministic unless the test controls randomness (`page.addInitScript` to stub `Math.random`) or the data is moved
  behind an API. "Pending payout" is derived as 15% of that random total.
- Date range: presets "Last 3M / 6M / 12M" and a Custom popover with From/To `type="date"`, validation
  (start after end, end after today) and Apply/Cancel/Escape/outside click.
- Bulk actions: `BulkActionBar` appears when courses are selected (checkboxes labelled "Select all courses" and
  "Select <title>"); actions publish/unpublish/delete/change category, delete confirmed in a dialog
  (`aria-labelledby="delete-bulk-title"`), calling `coursesApi.update` / `remove`.
- **Dependency check:** `RevenueChart.tsx` imports `recharts`, but I could not find `recharts` in `package.json`.
  If it is really missing, the dashboard will fail to compile and no E2E can pass. Check `npm ls recharts` after install; if missing
  that is a separate fix to raise first.

### Plan

Add `e2e/instructor-revenue.spec.ts`, structured like `enrollment.spec.ts` (`describe`, `beforeEach` with route mocks):

1. `beforeEach`: set auth cookie and localStorage; mock `**/api/v1/users/**` instructor stats (courses list, totals);
   stub `Math.random` with `addInitScript` so chart values are stable; mock categories and course update/delete routes.
2. **Happy path (dashboard):** heading "Instructor Dashboard"; stat cards show mocked totals; chart renders after the loading state
   (assert the range label text and the number of bars/x-axis ticks for the 12M default).
3. **Date range filtering:** click "Last 3M" -> range label and tick count change (3 months); open Custom, set From/To,
   Apply -> label shows the custom range and the trigger is highlighted.
4. **Edge/failure cases:** invalid custom range (From after To) shows the message and disables Apply; Escape closes the popover
   without changing the range; stats API returns 500 -> page still renders with zeros (code uses `.catch(console.error)`);
   empty course list shows "No courses yet".
5. **Bulk actions (courses page):** select two courses -> bar shows "2 selected"; choose Unpublish, Apply -> assert the PATCH
   requests; Delete -> confirm dialog, cancel keeps rows, confirm calls delete; "Change category" keeps Apply disabled until a category is chosen.
6. CSV export button: assert a download event with the expected filename pattern `revenue-<from>-to-<to>.csv`.

### Verification

`npm run test:e2e` on chromium, firefox, webkit, Mobile Chrome and Mobile Safari. Mobile widths hide the volume
slider elsewhere, so check that the date picker and bulk bar layouts are still operable (the picker uses `flex-wrap`).
Watch for WebKit's handling of `type="date"` `fill`. Lint and format.

### Risks

Random chart data (above); the 500 ms simulated delay (use auto-waiting assertions, not `waitForTimeout`);
the possible missing `recharts` dependency; the date-dependent "This Month" card (compute expected values from stubbed data
and a fixed clock via `page.clock` if available in the Playwright version).

## #233: E2E for the notification feed

### Current state

- The `/notifications` page (`src/app/notifications/page.tsx`) lists notifications from `notificationsApi.list()`,
  with colour-coded type badges (`TYPE_COLORS`), a "Mark all read" button, an unread counter ("N unread" / "All caught up"),
  a loading spinner and an empty state ("No notifications yet").
- **Mark as read:** clicking an unread row calls `notificationsApi.markRead(id)` and updates local state; read rows are dimmed
  (`opacity-60`) and not clickable. "Mark all read" calls the API and then reloads the list.
- **Navigation:** the page does *not* navigate when a notification is clicked. Click-through navigation exists only in
  `NotificationDropdown.tsx` (`router.push(notificationHref(n))`), which is the surface the issue names. The issue's
  "navigating from a notification" therefore applies to the header dropdown (bell -> row -> destination), not the page.
- `notificationsApi.list()` falls back to localStorage when the request fails, and the store falls back to
  `MOCK_NOTIFICATIONS`, so a failed API call in a test may still show data. Mock the route explicitly (status 200 for data,
  also a case where the fallback kicks in).
- Accessibility notes affecting locators: rows are clickable `div`s with no role, so tests can only locate them by text. Unread rows
  have no accessible "unread" indicator (only a colour dot). If the team later makes rows buttons, locators should be role-based.
  Not changed here, but worth a note on the issue.

### Plan

Add `e2e/notifications.spec.ts` following `enrollment.spec.ts` (auth cookie/localStorage as in `video-player.spec.ts`;
`page.route('**/api/v1/notifications**')`):

1. **Feed rendering:** three notifications (unread, read, different types). Assert title/message, the badge text
   (e.g. "enrollment confirmed"), the "2 unread" subtitle and "Mark all read" button.
2. **Mark one as read:** click an unread row -> a PATCH/POST request to the mark-read endpoint is sent with the right id
   (wait for the request, not a timeout), the unread count decrements and the row becomes dimmed.
3. **Mark all read:** click "Mark all read" -> request sent, subtitle becomes "All caught up", the button disappears.
4. **Empty state:** list returns `[]` -> "No notifications yet" and "All caught up".
5. **Failure/edge case:** mark-read returns 500 (note the page currently has no error handling there; the test should record the
   current behaviour and, if it is an unhandled rejection, flag it on the issue) and the list endpoint failing -> falls back to
   stored data / empty state without crashing.
6. **Navigation from the dropdown:** open the bell in the header (`aria-label` "Notifications — N unread"), click a row,
   assert it is marked read and the URL changes to the type's destination (`ENROLLMENT_CONFIRMED` -> `/dashboard/courses/<id>/learn`,
   `default` -> `/notifications`); "View all notifications" link goes to `/notifications`.

### Verification

`npm run test:e2e` across all configured browsers; mobile projects may render the header bell inside a different container
(the dropdown is in `Header.tsx`), so check the locator works at the Pixel 5 / iPhone 12 viewports or scope those cases to desktop
with `test.skip` on mobile and a comment. Lint and format.
